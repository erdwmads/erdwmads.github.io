# UI Invariants

This site is not a generic academic homepage. Its identity is an astromineralogy research archive with an Interface 2046 / Mission Log language.

## Preserve These Concepts

- Mission Log
- Mission Index
- SOL numbering
- Current Focus
- Analytical Pathway
- Interface 2046
- Astromineralogy (the research field; it replaced "Cosmic Mineralogy" on 2026-10-09)
- Orgueil CI1 chondrite
- Dolomite in Orgueil CI1

Do not remove these concepts during refactors unless the owner explicitly changes the site direction.

Mission Log content is private. The public site may preserve its shell and visual language, but detailed entries are available only from the encrypted archive after the protected unlock flow.

That privacy covers entry text only. Mission Log images are ordinary public static assets; see "Mission Log images are not protected" in `docs/content-workflow.md`.

## Theme Behavior

The initial theme is applied before the CSS finishes loading. Keep that early theme preload behavior to avoid flashing.

Current assumptions:

- `localStorage` key: `mads-theme`
- theme values: `light`, `space`
- attributes/classes used by CSS: `data-theme`, `data-theme-space`, `body.space-mode`

Do not move initial theme selection to the end of the page.

## Ambient FX

Owner decision (since b8ab393): FX is on by default on desktop, and off at 760px and below and with reduced motion. This is the one place that records the default; other docs point here. Only the owner changes it.

Current behavior (`public/assets/js/ambient-space.js`):

- `localStorage` key: `madsAmbientFxEnabled`; FX is on unless it reads `'0'`. Switching FX off stores `'0'` (on stores `'1'`).
- `(max-width: 760px)` and `prefers-reduced-motion: reduce` turn FX off whatever is stored
- the layer stays low power: it pauses while the page is hidden, idle or in low-power mode, and while the Mission Log viewer or the mineral atlas is open
- FX button is generated by `ambient-space.js`, not hard-coded in HTML; its visible "FX On" / "FX Off" text is its name, with `aria-pressed` and a hidden description
- OFF should remove the ambient layer, not merely hide it
- the home entrance (`CosmicArrival.astro`, `src/scripts/arrival/`) is skipped when FX is stored as `'0'`, with reduced motion or Save-Data, with a URL hash, and after it has played once in the session (`sessionStorage` `mads-cosmic-arrival-v1`); it closes if the scene is not ready within 3 s. Closing does not move focus by script: the skip link follows the dialog, so the first Tab reaches it. After a replay, focus returns to Replay.

Keep the gold ratios unless intentionally redesigning ambient visuals:

- stardust gold ratio: 18%
- meteor gold ratio: 7%

## Desktop And Mobile Mission Log Images

Both are implemented in `public/assets/js/mission-lightbox.js`. There is no thumbnail strip or hydration helper: entry images are ordinary lazy `src` images (720w WebP thumbnails written by the publisher), and the viewer loads `data-full-src`.

Desktop:

- lightbox behavior is allowed
- the open viewer is modal: the other children of `body` are `inert`, Tab and Shift+Tab cycle Close, Previous and Next, Escape closes it, and focus returns to the opening figure

Mobile/coarse pointer:

- `mission-lightbox.js` sets `html.mobile-mission-lightbox-disabled` from `(hover: none), (pointer: coarse), (max-width: 760px)` and updates it when that query changes
- Mission Log images are figures, not buttons: no `role`, `tabindex` or label is added, and taps and Enter/Space do not open the viewer
- captions are visible inline
- hover/open affordances are suppressed by the legacy `style.css` block "Mobile Mission Log: Disable Large Image Lightbox"; keep that class name

After unlock, focus moves to the session notice ("Mission Log unlocked · N records…"). The Mission Index list is a labelled region, not a live region.

## Header Controller And Page Classes

- `LegacyShell.astro` inlines `public/assets/js/site-header.js` as `<script is:inline data-site-header>` directly after `</header>`, so the mobile navigation is ready before first paint. Soft navigation skips it. Do not add it back to `commonScripts` in `src/data/site.ts`.
- Body `ui-page-*` classes come only from `LegacyShell.astro` (`current`, plus the optional `pageClass`); soft navigation copies them from the fetched page. There is no client-side page-class map.

## Floating UI Placement

Avoid viewport-height floating placement for persistent controls. Use stable bottom/right offsets and maintain clearance from existing Target / Phase / Mode cards.

## Light Mode And Space Mode

Light Mode is not just an inverted Space Mode. Some controls need a pale glass / champagne skin in Light Mode and a darker capsule in Space Mode.

When changing a component, check both themes explicitly.

## Stylesheet Ownership

The 16 files of `stylesheets` in `src/data/site.ts`, in cascade order (all in `public/assets/css/`):

1. `style.css`: legacy compatibility rules only; do not append new component work here (`npm run audit:css:check` fails if it grows).
2. `tokens.css`: current Light/Space theme tokens (`--evo-*`).
3. `shell-evolution.css`: header, navigation, theme controls, mobile shell, and supporting HUD visibility.
4. `research-log-evolution.css`: Research Log dashboard, protected gate, graduation research surfaces and the Mission Log photo grid.
5. `observatory.css`: shared visual language and `--obs-*` tokens; home composition, records, Paper Shelf cards and narrow-desktop navigation.
6. `observatory-experience.css`: glass shell, prism controls, the moving navigation marker, the display-settings dock (`.obs-fx-*`), presentation view and Mission Index cards.
7. `mineral-interactions.css`: event-driven mineral effects and the Evidence Atlas (`.atlas-*`).
8. `research-scale.css`: published microscopy scale figures (`.research-scale`).
9. `planetary-explorer.css`: planetary field guide viewer (`.planetary-*`, including `.planetary-sr-only`).
10. `typography.css`: local Montserrat, the serif for personal names, and equal-width theme labels.
11. `site-refinement.css`: whole-site reading hierarchy, skip link, editorial cards, CV, footer and settings clearance; owns the shared `.visually-hidden` utility.
12. `review-refinement.css`: mobile navigation fallback before `data-nav-ready`, CV print, reference tools, and scene loading/recovery states.
13. `research-reading.css`: Research page section guide, question, Analytical Pathway grid (`.research-workflow`) and context cards.
14. `experimental-folio.css`: page `h1` scale, home hero composition and the Photography contact sheet.
15. `image-inspector.css`: image inspector for the published microscopy figures.
16. `quiet-observatory.css`: the final shared frame: one control grammar for buttons and filters, plus the mission notebook and Origins study workspaces.

Two component stylesheets are not in that list: `src/scripts/sample-missions/style.css` (sample-return mission workspace on Ryugu & Bennu) and `src/scripts/origins-study/style.css` (Origins study page). `LegacyShell.astro` imports both, so Astro bundles them into a separate `_astro/*.css` file that loads after `site.css`.

The evolved styles remain globally loaded because soft navigation replaces the page body without replacing the document head. A future page-specific split must first teach soft navigation to synchronise stylesheet links.

Pages link one generated bundle, `assets/css/site.css`, built from these files in the order of `stylesheets` in `src/data/site.ts`. The bundle only strips whitespace and comments, so ownership and cascade order are exactly as in the source files. Keep editing the owner files; the file-level `?v=` strings were replaced by one content hash on the bundle.
