## Ambient FX

Owner decision (since b8ab393; phones changed 2026-11-18, decision E103, delegated by the owner to the director): FX is on by default at every width and off with reduced motion. At 760px and below it runs as a lite field: 44 dust motes (half the 88 of the phone field before b2b150b), no pebbles and one meteor every 5.2 s (half its rate), built only after the page has loaded and the browser is idle; the orrery, the rail and the reading spine stay off on phones (`interface-2046.js`, `mads-mobile-lite`), and so does the pointer edge light (coarse pointers). The guard measured on a phone profile (390 x 844, 4x CPU, Lighthouse network) before and after: LCP and CLS within the baseline and no long task while the page idles. This replaces the earlier "lightweight phones" rule. This is the one place that records the default; other docs point here. Only the owner changes it.

Current behavior (`public/assets/js/ambient-space.js`):

- `localStorage` key: `madsAmbientFxEnabled`; FX is on unless it reads `'0'`. Switching FX off stores `'0'` (on stores `'1'`).
- `prefers-reduced-motion: reduce` turns FX off whatever is stored; `(max-width: 760px)` selects the lite field (`.ambient-space-layer.is-lite`), and crossing that width rebuilds the field at the other density
- the layer stays low power: it pauses while the page is hidden, idle or in low-power mode, and while the Mission Log viewer or the mineral atlas is open
- FX button is generated by `ambient-space.js`, not hard-coded in HTML; its visible "FX On" / "FX Off" text is its name, with `aria-pressed` and a hidden description
- the button sits in the Visual effects panel of the floating dock (`.obs-fx-dock`, `observatory-interactions.js`). At 760px and below the dock is hidden and the same panel, with the Target / Phase / Mode readout, moves into the navigation sheet after the theme toggle (decision R3, amended by E136)
- OFF should remove the ambient layer, not merely hide it
- the home entrance (`CosmicArrival.astro`, `src/scripts/arrival/`) is skipped when FX is stored as `'0'`, with reduced motion or Save-Data, with a URL hash, and after it has played once in the session (`sessionStorage` `mads-cosmic-arrival-v1`); it closes if the scene is not ready within 3 s. Closing does not move focus by script: the skip link follows the dialog, so the first Tab reaches it. After a replay, focus returns to Replay.

Keep the gold ratios unless intentionally redesigning ambient visuals:

- stardust gold ratio: 18%
- meteor gold ratio: 7%

## Desktop And Mobile Mission Log Images

Both are implemented in `public/assets/js/mission-lightbox.js`. There is no thumbnail strip or hydration helper: entry images are ordinary lazy `src` images (720w WebP thumbnails from `npm run images:derive`; the publisher points `src` at them), and the viewer loads `data-full-src`.

Desktop:

- lightbox behavior is allowed
- the open viewer is modal: the other children of `body` are `inert`, Tab and Shift+Tab cycle Close, Previous and Next, Escape closes it, and focus returns to the opening figure

Mobile/coarse pointer:

- `mission-lightbox.js` sets `html.mobile-mission-lightbox-disabled` from `(hover: none), (pointer: coarse), (max-width: 760px)` and updates it when that query changes
- Mission Log images are figures, not buttons: no `role`, `tabindex` or label is added, and taps and Enter/Space do not open the viewer
- captions are visible inline
- hover/open affordances are suppressed by the block "Mobile Mission Log: Disable Large Image Lightbox" in `src/styles/folio/components/lightbox.css`; keep that block name and the class name (`npm run check:site` and the style contract look for both)

After unlock, focus moves to the session notice ("Mission Log unlocked · N records…"). The Mission Index list is a labelled region, not a live region. At 1200px and wider the Mission Index is a sticky ledger beside the entries; below that it is a `<details>` disclosure whose `open` state `mission-index.js` keeps in step.

## Header Controller And Page Classes

- `SiteShell.astro` renders the header (`SiteHeader.astro`) and inlines `public/assets/js/site-header.js` as `<script is:inline data-site-header>` directly after it, so the mobile navigation is ready before first paint. Soft navigation skips it. Do not add it back to the script registry in `src/data/site.ts`.
- Soft navigation (`public/assets/js/legacy-navigation.js`) re-runs only body scripts marked `data-page-script`: the page-scoped scripts `getPageScripts` renders, any inline script in its `inlineHtml` marked by hand, and research.html's legacy-link forwarder (`src/scripts/inline/research-forward.js`). Other scripts inside `<main>` are swapped in inert, and a bundled module loads only if the document does not have it yet. Shell scripts and the inline theme preload, header controller, entrance opener and JSON-LD never run twice.
- Every `assets/js/*.js` URL carries `?v=` with a content hash of the file, added at build time (`src/lib/script-version.ts`); nobody edits a version string. `npm run check:site` checks the hashes and that exactly the page-scoped scripts carry `data-page-script`.
- A fetched page whose `<head>` names a module script or stylesheet the open document did not load comes from a newer deploy, so it opens with a full page load (a reload after Back or Forward) instead of a `<main>` swap.
- The heavier features (planetary explorer, Origins, sample missions, image inspector) load only on pages that contain their root element: `src/scripts/feature-loader.js`, imported by the `SiteShell.astro` module, imports them on load and on `mads:soft-nav-content`, and starts fetching Origins while the pointer or focus is on its header link. Each one initialises itself when imported and keeps its own soft-navigation listeners. Until a scene is ready, a still poster (`src/components/ScenePoster.astro`, `public/assets/img/posters/`) fills its stage.
- Body `ui-page-*` classes come only from `SiteShell.astro` (`current`, plus the optional `pageClass`); soft navigation copies them from the fetched page. There is no client-side page-class map.

## Content Security Policy

- GitHub Pages cannot send headers, so every page carries one `<meta http-equiv="Content-Security-Policy">` as the first element after the viewport meta (`SiteShell.astro`; the Sample Cabinet stub has its own). The policy lives in `src/lib/csp.mjs`: everything from this origin, no third-party scripts, styles, fonts, images, frames or connections.
- Inline scripts run only by hash. Each executable inline script is a file in `src/scripts/inline/` (theme preload, entrance opener, research.html forwarder) or `public/assets/js/site-header.js`, registered in `src/lib/inline-scripts.ts`, rendered with `set:html` and hashed from the same string at build time. A new inline script must go there, and one policy covers all pages because soft navigation keeps the first page's policy. JSON-LD needs no hash. No inline event handlers or `javascript:` URLs.
- `'wasm-unsafe-eval'` and `worker-src blob:` exist for the Draco decoder of the OSIRIS-REx model on Ryugu & Bennu (a blob: worker that compiles WebAssembly); without them the spacecraft never loads. `img-src data: blob:` covers CSS data URIs, canvas snapshots and GLB textures. `style-src 'unsafe-inline'` stays because pages and scripts set style attributes.
- `npm run check:site` enforces, over every generated page, the meta before the first script, one identical policy with exactly these directives, a hash for every inline script and no unused hash, and the no-external-request rule (no off-origin `src`/`href` in scripts, stylesheets, images, frames or media, and no off-origin CSS `url()`). The scanner lives in `src/lib/csp.mjs`, with unit tests in `src/lib/csp.test.mjs`. Plain links to other sites are fine.
- The Mission Log publisher runs the same scanner over each entry's `bodyHtml` and refuses, with nothing written, an entry with an off-site image or media, an inline event handler or a `javascript:` URL, which the policy would block silently after unlock.

## Light Mode And Space Mode

Light Mode is not just an inverted Space Mode. Theme-dependent control faces are tokens: the theme toggle, for example, is a champagne face in Light Mode and a darker capsule in Space Mode (`--obs-toggle-face`).

The palette is "Ink & Brass" (adopted 2026-11): Space is ink navy (ground `#0f1625`, surfaces `#171d2c` / `#202735`) with warm off-white text and a champagne accent (`#d2bb8f`); Light is warm ivory paper (`#f7f3eb`, surface `#fcfaf5`) with ink text and a brass accent (`#765725`). Links are steel blue in both (`#a6c1df` / `#355781`). Interactive borders (`--obs-control-border`: `#727a87` Space, `#857c6f` Light) keep 3:1 on every ground, hover and selected surface. Each theme uses one accent, sparingly: at most three resting brass marks in one viewport (kickers, the selected state, the Research Log signal); light that answers the pointer (the hover glow, the edge light, a lit row) is not counted, and there is never more than one at a time. Focus rings use the link colour (the Paper Shelf search box keeps the old brass ring, owner, 2026-11-18). Content boxes give way to hairlines (`--obs-hairline`, `--obs-rule`). Controls are the faced boxes: they carry a metallic sheen or the old site's opaque metal face (secondary buttons, the effects button, the planetary explorer's buttons) and a soft shadow, glow under a hovering pointer and sink into an inner shadow when pressed (`components/surface-light.css`); besides them only the old glazed panels have a face (the Research Log card, the sample-mission player and controls, the Planetary CI panel, the card drawn behind the 404 index); the Paper Shelf filters are the old flat boxes (the pressed one a highlight face behind a brass border), the Home keywords the old pills (with the old glass highlight band and glint, drawn without blur, as on the Research Log card, the 404 card and the docked effects panel; E097), and the Mission Log viewer's buttons the old glass. Text glows only where the old site's did (owner, 2026-11-18: "all of my previous effects"): the Light brand line, the footer and the kickers, which also begin with a glowing brass star bead, the site name and the headings in main (a soft light halo in Space, a white halo in Light; owner decision E116, the values of the old dormant rules), and in the decorative instruments the orrery's planet labels and the entrance's title and sky labels (a dark legibility shadow), as the hints over the Origins and sample-mission scenes; body text, links and controls never glow. A CV, Paper Shelf or Home timeline record under a hovering pointer takes the old record glow (a faint depth; a paper's rule turns to the glass edge) and never moves (E105). Controls rest on `--obs-control-shadow` and glow with `--obs-control-glow`; hover changes the face, the border and the shadow, never the size or text colour. The old small feedback motions are back and move no hit target away from the pointer: a hovered header link rises 1 px onto its lit face, the Onward arrow nudges, the gate sends a light sweep across itself, and the header's orbit trace glides along its bottom edge every 12 s (fine pointers, FX on, motion allowed). The default effects intensity, Immersive, carries the old glow strength. Night plates and the presentation view (`.on-night`) keep the Space colours in either theme; the Mission Log viewer follows the page's theme as the old one did (a dark veil in Space, pale paper in Light).

The Bennu backdrop, the solar-system band and the old graticule return (owner, 2026-11-18) as pseudo-elements of body and html, never preloaded and never the LCP element; the source images and `scripts/generate-site-backgrounds.mjs` are restored (`components/backdrop.css`). They carry the old site's strengths: Space Bennu at .4 opacity on Home and .16 elsewhere, Light .1 and .045 (sepia), so the two themes stay distinct; the band shows the planets as strongly as the old header did. The graticule is a faint blueprint grid in both themes, in Space with a blue-grey haze toward the window edges and a diagonal brass light. With a script, both images wait until the page has loaded (Bennu then fades in; the band keeps its veil meanwhile), so they never compete with the page's own largest image; without one they show at once. To keep header text at 4.5:1 over the brighter strip, the Space band is .96 opaque under a .72 to .82 veil and the Light band under a .89 to .92 veil. Both stay with FX off and reduced motion, as on the old site; more contrast removes Bennu and the graticule and makes the band opaque; forced colours and print show neither. Text keeps its contrast over them (`backdrop-contrast.browser`); to tune, lower `--obs-backdrop-opacity*` or raise `--obs-band-veil`, never move or enlarge text.

Every colour is an `--obs-*` token in `src/styles/folio/00-tokens.css`, the only file that may name a theme (`[data-theme`); components read tokens and never name a theme. The first-paint colours in `src/scripts/inline/theme-preload.js`, the inline style and both `theme-color` metas in `SiteShell.astro` must equal the page grounds (`scripts/theme-preload.test.mjs` and `scripts/tokens-contract.test.mjs` check this). Body text keeps at least 4.5:1 and interactive boundaries 3:1 in both themes.

When changing a component, check both themes explicitly.

## Stylesheet Ownership

Every style lives in `src/styles/folio/`. Its architecture record, `src/styles/folio/README.md`, is the owner document: the files in cascade order, the header line each file carries (owner, budget, `!important` allowance), the lint, the token and naming rules, the specificity limits, the breakpoints and the motion rules. Read it before changing CSS.

In short:

- Pages link one stylesheet, `assets/css/site.css?v=<content hash>`, generated at build time (`src/pages/assets/css/site.css.ts`, `src/lib/stylesheet-bundle.ts`) from the one `stylesheets` array in `src/data/site.ts`. The bundle only removes whitespace (each file keeps a `/*! path */` marker), so ownership and cascade order are exactly as in the source files. Edit the owner files, never the bundle.
- No CSS lives in `public/`, and no component imports CSS or carries a `<style>` (the shell's first-paint style is the one exception). A new stylesheet goes into `src/styles/folio/` and into `stylesheets`; the build fails on a listed file that is missing or a file that is not listed.
- `npm run audit:css:check` runs the lint (`scripts/audit-css.mjs`): per-file budgets from the headers, the specificity limits, `!important` only in `02-reset.css`, `05-utilities.css`, `states/motion.css` and `states/print.css`, no `@layer`, `@import`, remote `url()` or nested rules, and `backdrop-filter` only on the selectors where the old site rendered a live blur in Edge (`blurAllowList`).
- `npm run check:site` fails on a CSS import under `src/`, a file missing or out of order in the bundle, a `.css` file under `public/`, and a page that links any stylesheet other than the bundle.

All styles stay globally loaded because soft navigation replaces `<main>`, not the document head. A page-specific split would also turn soft navigation into full page loads, because a fetched page whose head names a stylesheet the open document lacks is treated as a newer deploy.
